# Plan 02-01: Wishing Piece Item Type

## Goal
Update the existing `ITEM_WISHING_PIECE` entry in `src/data/items.h` so the item shows a USE button in the field (`.type = ITEM_USE_FIELD`). The item is used contextually via den interaction scripts, so the field use function stays as `CannotUse` for now — this satisfies ITEM-02 (overworld-only) without requiring a standalone bag-use flow.

## Context

**The entry already exists** — `ITEM_WISHING_PIECE` is defined at constant `195` in `include/constants/items.h:259` and the item table entry lives at `src/data/items.h:3565–3579`:

```c
[ITEM_WISHING_PIECE] =
{
    .name = _("Wishing Piece"),
    .price = 20,
    .description = COMPOUND_STRING(
        "Throw into a\n"
        "{PKMN} Den to attract\n"
        "Dynamax Pokémon."),
    .pocket = POCKET_ITEMS,
    .type = ITEM_USE_BAG_MENU,          // ← change to ITEM_USE_FIELD
    .fieldUseFunc = ItemUseOutOfBattle_CannotUse, // Todo
    .flingPower = 50,
    .iconPic = gItemIcon_WishingPiece,
    .iconPalette = gItemIconPalette_WishingPiece,
},
```

**Type values:**
- `ITEM_USE_BAG_MENU = 4` — stays in bag menus; no USE button anywhere
- `ITEM_USE_FIELD = 2` — shows USE button in overworld; battle bag does not show it

**Why keep `ItemUseOutOfBattle_CannotUse`:** The actual den activation flow is triggered by the den interaction script (`checkitem`/`removeitem`), not by selecting USE from the bag. Using it from the bag standalone will show "Can't use that here." which is acceptable. The `// Todo` comment signals future work.
