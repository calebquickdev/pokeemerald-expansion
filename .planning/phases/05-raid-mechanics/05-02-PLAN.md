Immediately after the closing `}` of this if/else block (before the `u32 effect = GetMoveEffect(gCurrentMove);` line), insert the threshold check:

```c
                if ((gBattleTypeFlags & BATTLE_TYPE_RAID)
                 && battler == B_POSITION_OPPONENT_LEFT
                 && !(gHitMarker & HITMARKER_PASSIVE_DAMAGE)
                 && !(gBattleStruct->moveResultFlags[battler] & MOVE_RESULT_NO_EFFECT))
                {
                    u32 hp    = gBattleMons[B_POSITION_OPPONENT_LEFT].hp;
                    u32 maxHp = gBattleMons[B_POSITION_OPPONENT_LEFT].maxHP;
                    if (gBattleStruct->raid.shieldPhase == 0 && hp * 4 < maxHp * 3)
                    {
                        gBattleStruct->raid.shieldHp    = 1 + gRaidCurrentStarRating;
                        gBattleStruct->raid.shieldPhase = 1;
                        if (hp * 2 < maxHp)
                        {
                            gBattleStruct->raid.shieldHp    = 1 + gRaidCurrentStarRating;
                            gBattleStruct->raid.shieldPhase = 2;
                        }
                    }
                    else if (gBattleStruct->raid.shieldPhase == 1 && hp * 2 < maxHp)
                    {
                        gBattleStruct->raid.shieldHp    = 1 + gRaidCurrentStarRating;
                        gBattleStruct->raid.shieldPhase = 2;
                    }
                }
```

Key decisions:
- `battler == B_POSITION_OPPONENT_LEFT` (value 1) is the boss; use the named constant.
- The nested `if (hp * 2 < maxHp)` inside the `shieldPhase == 0` branch handles a single massive hit that drops HP through both thresholds at once — it immediately grants the second shield set and sets `shieldPhase = 2`, skipping phase 1 entirely.
- The `!(gHitMarker & HITMARKER_PASSIVE_DAMAGE)` guard prevents burn/poison/weather damage from activating shields.
- `!(MOVE_RESULT_NO_EFFECT)` guard prevents moves that were blocked from triggering shields.
- Multiply-based fraction comparison (`hp * 4 < maxHp * 3` for 75%) avoids division and overflow risks at the u16/u32 sizes in use here.
- `gRaidCurrentStarRating` is accessible because Plan 01 added `#include "raid_den.h"` to this file.
